# 「耳边」(erbian) 实现计划

> **For Hermes:** 本计划为隔夜自主交付契约。按阶段顺序执行；每阶段以"验证通过 + commit"收口。
> 构建/测试循环遵循 skill `android-ci-build`（push → 后台轮询 → triage → artifact）。

**Goal:** 交付可装机的「耳边」APK：长按电源键唤醒浮层 → 文字发给 Hermes Agent → 频道双向对话 + 画像/日程/设置四页 + 内嵌 MCP + 自动化模拟器验收。

**Architecture:** 方案一（设计文档 §三）。App=耳朵+频道（Kotlin/Compose 单包），脑子在 Hermes（webhook 上行 / 本机 REST 回程 / MCP 暴露 App 文件与日志）。

**Tech Stack（全部沿用 ai-diary CI 实证版本）：**
AGP 8.5.2 / Kotlin 2.0.20 / Compose plugin 2.0.20 / KSP 2.0.20-1.0.25 / compileSdk 35 / minSdk 31 / Java 17 / Compose BOM 2024.09.00 / Room 2.6.1。新增：Ktor（server CIO + client，版本以首次解析成功为准，候选 2.3.13）、MCP Kotlin SDK（`io.modelcontextprotocol:kotlin-sdk`，失败则走 T21 降级方案）、Shizuku API（`dev.rikka.shizuku:api`）。

**仓库：** `lantianhcgp/erbian`（私有）+ 本地 `~/erbian`，主分支 `master`。

**自主激活链（无需用户）：** rish（shell）→ `pm install` 装机、`pm grant` 授权、写三件唤醒设置、`input keyevent --longpress 26` 实测、`screencap` 截图供视觉核验。App 侧 Shizuku 仅用于后续自愈（可选授权）。

## Phase 2 — core 纯逻辑（本地 TDD 红绿循环）

所有纯逻辑放 `core/src`（app 经 `kotlin.srcDir("../core/src")` 复用；core/test 本地+CI 双跑）。

### Task 4: JSON 手写编解码（零依赖）
- Create: `core/src/json/Json.kt`（encode/decode：object/array/string/number/bool/null + 转义；`JsonValue` sealed）
- Test: `core/test/json/JsonTest.kt`（往返、转义、嵌套、坏输入抛异常）
- 契约：消息 schema（设计文档 §三）全程用它序列化——**不用 kotlinx-serialization**（保 core 独立可测）

### Task 5: 消息模型与去重
- Create: `core/src/model/Message.kt`（id/kind/body/ts/status/meta；kind 枚举 = user_record|reply|proactive|summary|todo_confirm|todo_result|error_notice；toJson/fromJson）
- Test: 往返 + 非法 kind + 缺字段默认值

### Task 6: 上行队列状态机
- Create: `core/src/queue/MessageQueue.kt`（enqueue→sending→sent/failed；30s 超时重试 1 次；id 去重；离线积压序列化持久化接口 `QueueStore`）
- Test: 状态转移全路径、重试一次后 failed、重复 id 忽略、恢复后补投顺序

### Task 7: HMAC 与 webhook 客户端契约
- Create: `core/src/net/Signature.kt`（HMAC-SHA256 hex，javax.crypto）+ `core/src/net/UplinkContract.kt`（POST body JSON 格式 + `X-Erbian-Signature` 头格式定义）
- Test: 签名向量比对（固定 secret/message → 固定 hex）；body 字段完整性

### Task 8: 摘要节流
- Create: `core/src/logic/SummaryThrottle.kt`（30s 前台去重窗口）
- Test: 窗口内拒绝/窗口外放行/时钟注入

### Task 9: 混合待办策略
- Create: `core/src/logic/TodoPolicy.kt`（输入文本 → auto / confirm / none；关键词规则：明确时间词+动作词→auto；"找时间/回头/有空"等→confirm；无动作→none）
- Test: ≥12 条中文样例（设计文档混合策略）

### Task 10: 唤醒设置状态机
- Create: `core/src/logic/WakeSettings.kt`（三键模型 + diff → RepairPlan（写哪些值）+ 期望值常量表）
- Test: 各当前值组合 → 计划正确

### Task 11: 下行消息解析
- Create: `core/src/model/InboundMessage.kt`（/api/message body：kind/meta.todo 结构 {title,start,endMillis,allDay,desc}）
- Test: 往返 + todo meta 缺省

## 全程纪律
1. push 前必跑 `scripts/precheck.sh`（语法预检）+ `scripts/core-test.sh`（逻辑红绿）
2. CI 用后台轮询，禁 sleep 阻塞；期间干下一个任务
3. 每 Task 收口 = commit（conventional commits）；每 Phase 收口 = push + CI 绿
4. 交付红线（memory）：绝不谎报——模拟器截图/真机截图必须 vision 亲眼看图 + 像素断言后才写入报告
5. rish 写设置前先记录原值；改挂了立即 restore（restore.sh 模式已在设计期验证）
6. 网络抖动对策：HTTP/1.1、重试、raw 优先；codeload/git 大流量通道今日不可用
